---
title: Meta
description: The _meta.amp metadata the adapter accepts on requests, emits on updates, and advertises on initialize.
---

Lifecycle requests carry Amp-owned settings under the `_meta.amp` namespace.
Unknown keys fail closed; foreign vendor namespaces are ignored. The reserved
`acp-go.dev/*` literals are never foreign: each one is either read or rejected
on every surface it can reach.

## Request metadata

```json
{
  "_meta": {
    "amp": {
      "options": {
        "env": {},
        "mode": "high"
      },
      "rawEvent": {
        "enabled": false
      }
    }
  }
}
```

## Accepted fields

| Field | Accepted values |
|---|---|
| `options.env` | Map of environment overrides, including the session's complete raw `PATH`. |
| `options.mode` | Any Amp mode; `low`, `medium`, `high`, `ultra` are advertised. No mode is refused here — the value reaches Amp's `-m` flag unchanged. The key may be omitted, which takes the advertised default, but a key present with an empty string names no mode and fails with the uniform unsupported error. |
| `options.model` | Present for symmetry; any value fails with the uniform unsupported error. |
| `options.outputSchema` | Present for symmetry; any presence fails with the uniform unsupported error. |
| `rawEvent.enabled` | `true` to stream `_amp/rawEvent` for the session. |

Unknown keys under `_meta.amp`, `_meta.amp.rawEvent`, or `_meta.amp.options`
fail closed. Foreign metadata namespaces are ignored.

## Environment composition

The prompt child's environment is composed in phases: `NativeEnvironment` from
the supplied host authority, or the ordinary process environment when no
authority is supplied; then `WithEnv`, `options.env`, the adapter-managed
`HOME` and `XDG_*` roots, and the trace carrier. A later phase replaces an
earlier value, so the managed residence cannot be redirected by any caller
value and the session's `options.env` owns the whole raw `PATH` the prompt
process runs with.

The `amp` executable is resolved and version-probed before any session exists,
against the static base alone — the authority's `NativeEnvironment`, or the
ordinary process environment, plus `WithEnv`. Children that are not prompts —
startup probes, thread export, thread delete, and account login — run on that
same static base plus their adapter-managed residence and the session's
`AMP_API_KEY` and `AMP_URL`. Every other `options.env` value, the raw `PATH`
among them, reaches the prompt child alone.

Windows resolves variable names without regard to case, so on Windows every
equal-fold spelling is one variable: `Path` supplied by `WithEnv` and `PATH`
supplied by `options.env` compose into the single `PATH` the session named. A
key that cannot be a variable name, and — on Windows — a single map that names
one variable under two spellings, are refused with the uniform invalid-params
error rather than resolved by chance.

## Emitted metadata

Every main-agent `agent_message_chunk` carries `_meta.amp.messageId`, and the
terminal main-agent value is repeated on the successful `session/prompt`
response. The same value is also placed in the ACP `messageId` field. Amp does
not expose a native message or turn id, so the adapter derives a UUID from the
frame's absolute position and exact bytes in the durable transcript mirror.
The derivation makes replay stable while keeping byte-identical assistant
frames in separate turns distinct. Delegated-agent frames never become the
terminal checkpoint identity.

`session/update` notifications derived from delegated-agent frames — subagents,
the oracle, and the Task tool — carry `_meta.amp.parentToolUseId`, the id of the
`tool_use` block that spawned the delegated agent. Main-agent updates omit the
key. See [Updates](/docs/reference/updates) for the tagged update kinds.

## Inbound content-block metadata

One key is read from an inbound `_meta` outside the `amp` namespace, and only on
an image content block: `acp-go.dev/handoff`, the local handoff input envelope.

```json
{
  "version": 1,
  "digest": "<64-character lowercase hex sha256>",
  "sizeBytes": 123456
}
```

It is strict — exactly these three fields, version `1` only — and it is read
only when `WithInputHandoffRoot` is set. On a block with non-empty `data` it is
ignored, because embedded data wins. See
[Models and config](/docs/features/models-config#local-handoff-input).

## Advertised capabilities

`initialize` advertises standard `promptCapabilities.image: true` plus
`_meta.amp.rawEvent` and `_meta.amp.sessionStore`. While a usable provider-auth
root is configured it also carries `_meta.amp.providerAuth`, listing the eight
enabled leg names:

```json
{
  "providerAuth": {
    "methods": [
      "_amp/auth/methods", "_amp/auth/authorize", "_amp/auth/callback",
      "_amp/auth/status", "_amp/auth/cancel", "_amp/auth/inventory",
      "_amp/auth/credential", "_amp/auth/disconnect"
    ]
  }
}
```

No `injectionKey` is advertised: a brokered Amp key is redelivered as
`AMP_API_KEY`, so `_meta.amp.options.providerAuth` is rejected as an
unsupported field. The block is absent entirely when no usable root is
configured, which is how a host learns the surface never came up. It omits fork and
elicitation capability metadata, because the adapter supports neither. Amp
does not expose authoritative per-model input modalities, so the adapter
publishes no model-specific image claims.

`agentCapabilities._meta` also carries `acp-go.dev/mediaEnvelope`, the bounds
this adapter actually enforces on inbound media:

```json
{
  "acp-go.dev/mediaEnvelope": {
    "maxBytes": 921600,
    "maxPromptBytes": 6291456,
    "maxDimension": 8000,
    "imageFormats": ["image/png", "image/jpeg", "image/gif", "image/webp"],
    "documentFormats": []
  }
}
```

- `maxBytes` is the effective per-image decoded bound: the tighter of
  `ImageLimits.MaxInputBytesPerImage` and Amp's 921,600-byte native envelope, so
  the default configuration advertises the native envelope.
- `maxPromptBytes` is the per-prompt aggregate decoded bound
  (`ImageLimits.MaxInputBytesPerPrompt`).
- `maxDimension` is Amp's 8,000-pixel native bound.
- `imageFormats` is the accepted media-type allowlist.
- `documentFormats` is always the empty array: Amp maps no media type to a
  native document representation.

The block is always present, and it is independent of every other
advertisement. `acp-go.dev/handoff` is added, as `{"version": 1}`, only when
`WithInputHandoffRoot` is set; its absence is how a host learns that its option
never reached this adapter.

Amp does not advertise `_meta["acp-go.dev/route"]`, stamp it on callbacks, or
validate a turn nonce — and that says nothing about the media envelope, which is
advertised regardless. Its prompt-builder nonce parameter is intentionally
ignored; cancellation remains structurally scoped by `sessionId`.

## Session lifecycle

`acp-go.dev/lifecycle` is the fourth reserved literal this adapter handles,
alongside `acp-go.dev/mediaEnvelope`, `acp-go.dev/handoff`, and
`acp-go.dev/route` — the one it deliberately does not implement. Unlike a vendor
namespace, a reserved literal is never ignored: every surface either reads it or
rejects it.

### Capability

The host offers on `InitializeRequest._meta`, carrying exactly one member:

```json
{"acp-go.dev/lifecycle": {"version": 1}}
```

The adapter places its `acp-go.dev/lifecycle` answer on
`InitializeResponse._meta` — the response's own top-level `_meta`, never inside
`agentCapabilities._meta`. Ordinary same-identity execution answers with no
authoritative quiescence claim:

```json
{
  "acp-go.dev/lifecycle": {
    "version": 1,
    "updatesOutsidePrompt": false,
    "authoritativeQuiescence": false,
    "activityKinds": []
  }
}
```

With `WithHostAuthority`, the same answer sets
`authoritativeQuiescence` to `true` and includes
`"quiescenceSource": "process-containment"`. Amp emits no activity kinds in
either mode.

The offer is strict: `version` must be the integer `1`, with no additional
member. The answer's proven-fact members are required, its activity array is
duplicate-free, and its quiescence source is present exactly when the answer is
authoritative. Malformed or trailing input is rejected with `-32602` naming the
exact path, for example
`{"error": "unsupported", "field": "_meta[\"acp-go.dev/lifecycle\"].version"}`.
With no offer, the response carries no lifecycle member and the connection has
no lifecycle surface: no envelope, correlation read, or lifecycle event.

### The prompt correlation value

When version 1 is enabled, every `session/prompt` carries:

```json
{"version": 1, "submission": {"submissionId": "opaque", "clientNonce": "opaque", "runId": "optional"}}
```

It is read and validated before dispatch, so a prompt this adapter cannot
correlate writes no frame to the harness. `submissionId` and `clientNonce` are
echoed verbatim on the acceptance event. With the extension not negotiated the
key must be absent, and a present one is rejected the same way.

### One incarnation per prompt

A prompt is one contained process, so a prompt is one whole native lifecycle
source lifetime. Each prompt opens its own stream with its own `streamId`,
sequence space, and entities:

1. `lifecycle_snapshot` — the first notification inside the prompt, stating the
   idle foreground, empty activity and action sets, and the quiescence fact this
   configuration can prove at stream open.
2. `prompt_accepted` — emitted once the native dispatcher owns the frame,
   echoing the submission identity.
3. `state_update` `running` — the transcript then flows as ordinary
   `session/update` notifications with **no envelope attached**.
4. `state_update` `idle` — the recorded outcome (`success`, `cancelled`,
   `limit`, `failed`) and, on every outcome but `failed`, the truthful stop
   reason. No ACP v1 stop reason names a failure, so a failed cycle records its
   outcome and states none; the v1 error carries the cause instead.
5. `quiescence_update` — emitted only under `WithHostAuthority`, once the native
   process handle's `Wait` proves the whole process tree settled, carrying the
   watermark that proof covers. A non-authoritative answer states no boundary
   fact, so its incarnation ends at the terminal `idle`.

The contained process exit fences the stream; the next prompt opens a new one.
Sequences are claimed before delivery is attempted, so a lost event leaves a
detectable gap rather than a silently contiguous stream.

`session/close` therefore always meets a stream that is already fenced, or a
session whose incarnation never opened, and it emits nothing on either: the
terminal state was reported by whatever fenced the stream, and a turn recorded
as `failed` is never restated as cancelled by the close that follows it. The
containment boundary is unconditional and already settled inside the prompt, so
a close that finds an uncertain boundary still fails.

The durable commit ran inside the prompt too, but a settlement whose commit
failed keeps its frames rather than dropping them, so `session/close` carries the
same commit as its own rung: it retries the retained frames on a detached context
before the session stops being addressable. A close that cannot land them fails
and reclaims nothing — the session keeps its identity and its frames, and the
close is retried once the store is back. A session already fenced for delete
commits nothing there, because the tombstone is the last write to that row.

`Agent.Close` owes the same rung. A commit a wire close would have made is made
there too, or reported as the store's refusal — never dropped with the wrapper.
A shutdown attempt is the last word: it boundedly joins and contains its owned
wrappers, releases local state where containment permits, removes every callable
ownership path, and memoizes its exact success or failure. A later `Agent.Close`
only observes that result and repeats no native, persistence, or cleanup command.
An unresolved native deletion is retried only while its isolated operation
state remains intact. If shutdown must release that state after the retry also
fails, the classified deletion failure is retained permanently; later shutdown
calls cannot turn it into success or repeat the command from a released home.

Settlement runs on a context detached from the request's, so a cancelled prompt
still commits the frames it streamed, states its terminal boundary, and fences
its stream before the response. The one exception is a settlement that cannot
complete: when the containment boundary or the durable commit itself fails, the
prompt fails with that error and emits **no** terminal `idle` — a boundary must
never claim a foreground prefix the store does not hold. The exact terminal
notifications remain pending; a close may first restore durability and then
retransmit them with their original stream/sequence identities. No later prompt
is admitted while that terminal proof is pending.

The outcome a settled turn recorded is the one its ACP response states. A cancel
landing while a turn is already failing does not turn that failure into a
cancelled result: the `idle` the host was just shown recorded `failed`, and the
response carries the matching turn-failure error.

### Carriers and refusals

Every lifecycle envelope rides its own identity-only `session_info_update`,
beside `sessionId` and `update` on the notification's `_meta`. No other
`sessionUpdate` variant carries one: message and tool-call patches have
per-entity `_meta` reduction semantics a conformant client may coalesce, which
would make an envelope placed there unrecoverable. The `_meta.amp` tags those
patches already carry are unaffected.

Amp has no permission or elicitation surface, so no action correlation value is
ever emitted. Every other inbound surface — `session/new`, `session/load`,
`session/resume`, `session/close`, `session/delete`, `session/list`,
`session/set_mode`, `session/set_config_option` in either variant, `logout`,
`authenticate`, `_amp/auth/*`, and
`_amp/session/fork` — rejects the key with `-32602` naming
`_meta["acp-go.dev/lifecycle"]`. A `session/cancel` carrying it
fails closed before the native interrupt and the cancel is never applied; being
a notification it carries no response frame, so that refusal is wire-silent.

`session/set_mode` does not exist on this adapter and answers `-32601 method not
found`. The refusal above is judged first: a reserved literal is never ignored
because the request was going to be refused anyway, so a `session/set_mode`
carrying the key answers `-32602` naming it, and so does the boolean
`session/set_config_option` variant this adapter otherwise rejects on its
discriminator.

Extension methods are judged the same way and before their names are resolved
at all. An `_`-prefixed method this adapter does not dispatch answers `-32601
method not found` on its own, but carrying the key it answers `-32602` naming
`_meta["acp-go.dev/lifecycle"]`: a method name is the caller's guess, while the
key is a literal this adapter reserves, and the guess is not the part that is
owed an answer first.
