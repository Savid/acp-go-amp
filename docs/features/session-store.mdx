---
title: Session Store
description: Wire a durable mirror of Amp threads for display replay, and understand its limits.
---

The session store is a host-provided durability layer that mirrors Amp thread
frames for display replay. It is not a substitute for the server-side Amp
thread — it exists so a host can reload and show past turns, not resurrect
native state.

## Wiring a store

Pass a store with `WithSessionStore`. The adapter ships an in-memory
implementation for tests and single-process hosts; a host that needs durability
across restarts implements the `SessionStore` interface over its own backend.

```go
err := ampacp.Serve(ctx, input, output,
	ampacp.WithExecutablePath("amp"),
	ampacp.WithSessionStore(ampacp.NewInMemorySessionStore()),
	ampacp.WithSessionStoreLoadTimeout(10*time.Second),
)
```

`WithSessionStoreLoadTimeout` bounds every store read — manifest and
transcript loads plus `session/list` — with a default of `10s`, so a slow or
hung backend never stalls a request. Store writes (`Replace`, `Delete`) run
under a separate fixed `60s` bound.

## Format and layout

`SessionStoreFormat` is `amp-thread-mirror-v1`. Records use these subpaths:

| Subpath | Contents |
|---|---|
| main | Manifest: `sessionId` (the adapter-minted ACP session ID), `nativeSessionId` (the Amp thread ID, absent until the first prompt turn creates the thread), `cwd`, `title`, selected `mode`, and Unix-millisecond create/update timestamps. |
| `transcript` | The full ordered Amp stream-JSON frame mirror for every prompt turn, including what a cancelled or failed turn streamed before it ended. |
| `_artifacts/images/<digest>.json` | Canonical typed image tool-result record containing embedded base64 and media type, or an HTTP(S) resource URI, plus native identity, checksum, and creation time. |

Each turn publishes the manifest, full transcript, and current image records
together in one `Replace` generation. Every turn does: a cancelled, failed, or
timed-out turn commits the frames it already streamed, so what the store holds
never diverges from what the client was shown. The commit runs after the turn
process containment boundary completes and before the terminal state the host
sees, so no settled turn claims a prefix the store does not hold. It also runs
on a context detached from the prompt request, so cancelling the request ends
the native turn and never the commit of what that turn already streamed. These
records back `session/load` replay. Auth environment values, settings files, and
API keys are never written to the store.

The first turn of a session publishes one additional generation the moment Amp
reports the thread it just created: the manifest plus the state already
committed, carrying no frames from the turn in flight. It exists so a crash
mid-turn can never leave a created server-side thread unrecorded.

`session/delete` stops the session's writes and waits out the commit already in
flight before its tombstone lands, so a turn settling alongside the delete can
never write the deleted session back into the store.

A tombstone is final in the store itself, not only in the adapter that wrote
it. Over a key `Delete` tombstoned, both `Append` and `Replace` write nothing,
clear nothing, and return success — the deleted state is already the caller's
answer. A store implemented over another backend owes the same guarantee: a
write already in flight when a delete lands reaches the backend regardless of
what the adapter above it believes, so refusing it is the backend's job.

Ordinary transcript frames retain the exact native Amp stream JSON. An
image-bearing tool-result frame is rewritten to stable artifact references
before raw-event emission or storage, preventing a second base64 copy or an
unredacted signed URL from entering those surfaces. Because Amp does not expose
message ids, the adapter derives each main-agent message UUID from the stored
assistant frame's absolute position and exact bytes. Replaying the mirror
reproduces the same identities emitted during the live turn.

Image records expire after 24 hours and are swept during initialization.
Deleting a session removes every artifact subpath. A replay that needs a
missing, expired, corrupt, or mismatched record fails with
`stage: "image_output"` and `reason: "storage_failed"`; it never omits the
image.

<Warning>
An HTTP(S) image result is stored with its original URI so replay can produce
the same resource link. Signed URIs may authorize access to output and make the
session store confidential application data.
</Warning>

## Restore is display-only

`session/load` hydrates the local mirror, verifies the thread can still be
addressed, and replays transcript frames to the client. `session/resume`
hydrates without replaying history.

<Warning>
A local transcript restore is not native thread resurrection. The mirror is the
durability boundary for display replay; the server-side Amp thread is the native
continuation unit.

Native continuation requires the live server-side Amp thread and AMP_API_KEY, so the mirror alone cannot continue a turn.

If the thread is deleted or unavailable, session/load can replay the local transcript for display, but a subsequent prompt fails with one terminal `native_state_missing` error — the adapter does not rebuild a thread from transcript text, because that would lose native state.
</Warning>

If a store write fails after a clean turn, the adapter keeps the frames in
memory and blocks the next prompt with a `mirror_unsynced` error until the write
succeeds, so the mirror never silently diverges from what Amp produced.
