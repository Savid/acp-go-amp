---
title: Troubleshooting
description: Map common failure symptoms to their causes and the fail-closed behaviors behind them.
---

The adapter fails closed: when native state is lost, a store write does not
commit, or a request asks for something Amp does not support, the operation
returns a loud error instead of silently recreating state. This page maps the
common symptoms to their causes and to the tests that pin each behavior.

## Symptoms

| Symptom | Likely cause | Where to look |
|---|---|---|
| Session start fails immediately with `amp_invalid_options` (`field: "env"`) | No `AMP_API_KEY` and no usable provider-auth broker | [Authentication](/docs/features/authentication); the adapter log carries the full explanation the wire token replaces |
| `initialize` or session start fails with `amp_invalid_options` and no `field` | The agent was constructed with several options it will not serve under | The joined Go error an embedding host receives names each one; see [ACP methods](/docs/reference/acp-methods#internal-errors-away-from-a-prompt-turn) |
| `session/load` or `session/resume` fails with `amp_restore_failed` | Unreadable store, foreign manifest, unparsable transcript, native restore failure, or an unavailable image artifact during load replay | The entry is left intact: repair the store or the harness and retry, or delete the session |
| Every operation on one session fails with `amp_session_poisoned` | `cause: "native_session_id_drift"` — a turn reported a thread id the session is not bound to; `cause: "native_session_id_invalid"` — a first turn reported a malformed thread id | Only `session/close` and `session/delete` still work; open a fresh session |
| First prompt fails immediately after a keyless auth bootstrap | The harvested key was not redelivered as `AMP_API_KEY` | Bind the credential through `WithEnv` or session env options before prompting |
| Prompt fails with `amp_turn_failed` (`cause: "process_exit"`) | Native `amp` exited non-zero | `message` carries the exit status and stderr tail |
| Prompt fails with `cause: "timeout"` | `WithTurnTimeout` deadline elapsed | Raise or unset the deadline; a timeout is a failure, not a cancel |
| Prompt is rejected with `field: "prompt.image"` | Invalid, animated, oversize, or native-envelope-breaking image input | Inspect `error`, `index`, `sizeBytes`, and `maxBytes`; see [Image input](/docs/features/models-config#image-input) |
| Prompt is rejected with `field: "prompt.resource"` | An embedded resource fails image validation or the decoded byte budget | Inspect the resource block named by the refusal; raster resources pass the image gates too |
| Prompt fails with `stage: "image_output"` | The adapter's own image artifact store broke; `reason` is always `storage_failed` | Check the session store; load replay reports artifact failures as `amp_restore_failed` |
| A tool call shows guidance text where an image was expected | The image was refused in place — undecodable, non-raster, oversize, mismatched media type, or an unreadable location | Follow the guidance in the tool content; the turn was not interrupted |
| Prompt fails with `amp_internal_failure` (`class: "native_state_missing"`) | Server-side Amp thread is gone | Start a fresh session with `session/new`; a mirror cannot resurrect it |
| Prompt blocked with `amp_internal_failure` (`class: "mirror_unsynced"`) | A prior store write failed | Restore the [session store](/docs/features/session-store) backend so the mirror can commit |
| Session start fails with `amp_internal_failure` (`class: "native_startup_failed"`) | The `amp` binary is unreachable, below the version floor, or its thread list is unreadable | The adapter log carries the native reason; check the `-path` binary |
| A `session/prompt` is rejected with `field: "_meta[\"acp-go.dev/lifecycle\"]"` and `error: "missing"` | The lifecycle capability is negotiated and the prompt carried no correlation value | Stamp the value on every prompt; see [Metadata](/docs/reference/meta#the-prompt-correlation-value) |
| An `_amp/*` request is rejected with `field: "params"` | The params body could not be decoded, or failed validation as a whole | Send a well-formed params object; the refusal precedes method resolution |
| Session start rejects an MCP server | Unsupported transport or bad field | [MCP](/docs/features/mcp) — only stdio and HTTP are accepted |
| `_amp/session/fork` returns an error | Amp has no fork surface | Fork requests are always rejected |
| Session start or resume rejects a model | Amp has no separate model option — `mode` selects the model | Remove the model option and choose a `mode`; the rejection is fail-closed |
| Live integration tests fail without `AMP_API_KEY` | Credential missing from the test environment | Export `AMP_API_KEY`; live tests fail rather than skip |

## Remote-thread loss

Amp stores conversation threads on the server side, so the remote thread is the
source of truth for continuation. When the thread behind a session no longer
exists, the adapter surfaces one terminal `native_state_missing` failure.
The local mirror remains available; only an explicit `session/delete`
tombstones it. Loading a session verifies that any
recorded native thread is still continuable: when the thread is gone, the load replays the
local transcript for display only, and the next prompt fails with `-32603`
`{"error": "amp_internal_failure", "class": "native_state_missing"}`. Reproduced by `TestActiveLoadVerifiesContinuability`
(`agent_session_test.go`) and `TestNativeMissingThreadAndDeleteFailureTombstone`
(`agent_test.go`).

<Note>
The `native_state_missing` class is terminal for that session: the native thread no longer
exists, so continuation is impossible. Recovery is a fresh bootstrap — open a new
session with `session/new` — not a retry of the same session.
</Note>

## Image failures

Input image failures are `-32602` and happen before Amp starts. The adapter
enforces 921,600 decoded bytes per image and 8,000 pixels per dimension even
when the matching `ImageLimits` field is zero. These conservative bounds come
from observed native failures; they are not a published service guarantee.
Amp stores image bytes as inline base64, so native storage limits can also
depend on the surrounding thread. Acceptance at these bounds on a long thread
is unproven, and passing local validation does not guarantee native acceptance.

Output failures reaching `-32603` with `error: "amp_turn_failed"`,
`cause: "transport"`, and `stage: "image_output"` always carry
`reason: "storage_failed"`; every other output verdict is refused in the tool
call's content without ending the turn. A missing or expired canonical
artifact makes load replay fail as `amp_restore_failed`; retrying replay cannot
restore swept bytes. See [Updates](/docs/reference/updates#output-refusals-and-failures) for
the complete taxonomy.

## Unsynced mirror

The adapter mirrors the remote thread's stream-JSON frames into the session
store. When a settled turn's store write fails — cancelled and failed turns
commit what they already streamed too — the turn is retained in memory and the
next prompt is blocked with a loud `mirror_unsynced` error;
once the store recovers, the exact retained frames are durably re-committed
before a new turn runs, so load replay still contains every turn. Reproduced by
`TestMirrorUnsyncedRetention` (`session_test.go`).

## Fork rejection

The Amp CLI's remote-thread model has no fork primitive, so the adapter rejects
the `_amp/session/fork` extension with the uniform unsupported error rather
than emulating a fork it cannot honor. Reproduced by
`TestForkExtensionUnsupported` (`agent_test.go`).

## Model selection

Amp has no separate model selector: its `mode` chooses the model. So the ACP
model option does not exist here — a default model configured on the agent
rejects every session start, and a per-session model on any
session-establishing path is rejected the same way — fail-closed with the
uniform unsupported `model` field error, never silently ignored. Reproduced by
`TestAgentLifecycleErrorBranches` and `TestRemainingAgentBranches`
(`session_test.go`). Choose the model through `mode` instead; see
[Models and config](/docs/features/models-config#config-options).

## Live-test credentials

The Amp CLI requires `AMP_API_KEY`. This repository's opted-in live integration
tests fail — not skip — when the credential is missing, so a live suite never
goes silently green over a credentials problem. Reproduced by
`requireAmpAPIKey` (`integration/helpers_test.go`).
